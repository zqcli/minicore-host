Weak storage introduces no ownership cycle or extended Session lifetime. The stream only reads Session state under a short lock; it does not call a child or perform I/O under that lock.

2. Accepted records are the identity authority
   The check reads output[original TurnId].tools; no second index or speculative ID reservation is introduced. The sole production insertion of these ToolRecords is observe_history, which runs inside the same Session lock as accepted history/cursor/save registration. Runtime awaits that history handoff before tools or another model request. Therefore a later response sees every previously accepted call, including calls from previous internal Loops.
   Output/tool records are not removed during a running Turn or compaction; full clearing occurs in reclaim_bodies only after resource retirement. Different public Turn IDs retain independent maps. The raw upstream ToolCallId is copied without renaming.

3. Rejection is before complete or partial Runtime assembly

4. Retry and legal-ID behavior
   ModelError::started creates nonretryable delivery, and Runtime retry policy explicitly rejects Started delivery or RetryHint::Never. Ordinary events/errors pass through unchanged; pre-delivery transient start errors retain Runtime's existing retry policy.

The tests correctly use an explicit later public Turn for partial-ID reuse and separately verify a legal pre-delivery retry, rather than claiming a retry Runtime does not support.
