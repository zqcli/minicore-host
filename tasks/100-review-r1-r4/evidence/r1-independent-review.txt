Checks:

1. Publication ordering: if the Agent shutdown phase was established before insertion, the new child receives it explicitly. If insertion wins first, the later normal shutdown scan includes the child. The early execution fence remains in place; the new check closes the awaited default-save gap without erasing an accepted Session or inventing rollback.

2. Creation barrier: state.creating is incremented at admission and decremented only in the owning task after create_session_work returns. Therefore it remains nonzero through the new child handoff and any initial delivery. shutdown_status_owned requires creating == 0 and creation_committed before parent resource retirement. Receipt Session success reflects the actual constructed and published object; final task reply and counter settlement follow handoff. Initial messages after force are truthfully refused via the existing execution fence.

3. Monotonicity: Agent.begin_host_shutdown_owned accepts only increasing phase (0 -> 1 -> 2). A stale captured graceful phase arriving after another thread applied force cannot downgrade the Session: its existing early return accepts already-draining/nonforce as idempotent, and host_stopping uses |= force. The patch does not reset either owner phase.

4. Locks: the new child call occurs after the AgentState guard's scope ends. Storage saves, publish_initial, and send_owned likewise remain outside that lock. No parent state lock crosses the new child operation or I/O.

5. Existing parallel-scan window examined and excluded as a blocker: an Agent can publish phase 2 before its lock-free child scan completes, while another same-phase scan returns early. I initially misread Host::run_shutdown's child-resource-release failure branch as returning; that was incorrect and the suspicion is withdrawn. host/shutdown.rs:230-265 records that temporary fault, then waits and loops. The Notify future is enabled before snapshots; Agent.changed is the Host.changed Arc installed by with_change_signal, Session.publish notifies the same parent Arc, and the original scan plus shutdown caller notify on completion. The Session release fence refuses premature release, so this cannot falsely publish Stopped; once the real child handoff completes, the next iteration recomputes/clears the fault and idempotently retries. This differs from the original R1, where the omitted child never received a fence. No new barrier is recommended on this basis.
